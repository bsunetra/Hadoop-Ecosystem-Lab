# 🧮 Experiment 3 – Hadoop MapReduce WordCount

## 🎯 Aim

To implement and execute a **WordCount MapReduce program** using Hadoop in both **Local Mode** and **Pseudo-Distributed Mode**, demonstrating the use of HDFS and YARN.

---

## 📌 Experiment Overview

This experiment implements the classic **WordCount** MapReduce program and executes the same job in two different environments:

1. **Local Mode**
2. **Pseudo-Distributed Mode**

Local Mode executes the MapReduce job using the local Linux filesystem without requiring Hadoop cluster services.

Pseudo-Distributed Mode executes the same job using **HDFS for storage** and **YARN for resource scheduling**, demonstrating a single-node Hadoop cluster architecture.

---

## 🛠️ Technologies Used

* Java
* Hadoop 3.3.6
* HDFS
* YARN
* MapReduce
* Ubuntu on WSL2
* Linux filesystem

---

# PART 1 – WordCount in Local Mode

## 🔹 Local Mode

In Local Mode, the MapReduce program runs in a single JVM and uses the normal Linux filesystem.

No HDFS or YARN cluster services are required.

### Workflow

```text
input.txt
    ↓
WordCount.java
    ↓
Mapper
    ↓
Shuffle & Sort
    ↓
Reducer
    ↓
output/part-r-00000
```

---

## 🔹 Map Phase

The Mapper reads each line of input and breaks it into individual words.

Each word is emitted as:

```text
(word, 1)
```

For example:

```text
hello world hello
```

produces:

```text
hello 1
world 1
hello 1
```

The implementation normalizes words by converting them to lowercase and removing punctuation.

---

## 🔹 Shuffle and Sort

Hadoop automatically groups values belonging to the same key.

For example:

```text
hello → [1, 1]
world → [1]
```

This grouped data is passed to the Reducer.

---

## 🔹 Reduce Phase

The Reducer adds all values associated with each word.

Example:

```text
hello → [1, 1]
```

becomes:

```text
hello → 2
```

The final output contains each word and its total count.

---

## 🔹 Local Mode Compilation

The Java program is compiled using Hadoop's classpath:

```bash
mkdir -p classes

javac -classpath $(hadoop classpath) -d classes src/WordCount.java

jar -cvf wordcount.jar -C classes/ .
```

---

## 🔹 Run WordCount in Local Mode

```bash
hadoop jar wordcount.jar WordCount input.txt output
```

The output can be viewed using:

```bash
cat output/part-r-00000
```

Example:

```text
dhoni 3
instagram 2
the 4
virat 6
```

# PART 2 – WordCount in Pseudo-Distributed Mode

## 🔹 Pseudo-Distributed Mode

In Pseudo-Distributed Mode, Hadoop services run on a single machine while behaving like a small cluster.

The architecture uses:

* NameNode
* DataNode
* SecondaryNameNode
* ResourceManager
* NodeManager

The MapReduce job uses:

* **HDFS** for storage
* **YARN** for resource scheduling

---

## 🔹 Hadoop Configuration

The following configuration files are used:

```text
config/
├── core-site.xml
├── hdfs-site.xml
├── mapred-site.xml
└── yarn-site.xml
```

### `core-site.xml`

Configures the default HDFS filesystem:

```xml
<property>
    <name>fs.defaultFS</name>
    <value>hdfs://localhost:9000</value>
</property>
```

### `hdfs-site.xml`

Configures:

* HDFS replication
* NameNode storage directory
* DataNode storage directory

### `mapred-site.xml`

Configures MapReduce to use YARN.

### `yarn-site.xml`

Configures the MapReduce shuffle service.

---

## 🔹 Format NameNode

The NameNode is formatted before starting the cluster:

```bash
hdfs namenode -format
```

> ⚠️ Formatting the NameNode again after data has been created can erase existing HDFS data.

---

## 🔹 Start Hadoop Services

Start HDFS:

```bash
start-dfs.sh
```

Start YARN:

```bash
start-yarn.sh
```

Verify the running processes:

```bash
jps
```

Expected processes:

```text
NameNode
DataNode
SecondaryNameNode
ResourceManager
NodeManager
```

Five processes indicate a healthy single-node cluster setup.

---

## 🔹 Load Input into HDFS

Create an HDFS input directory:

```bash
hdfs dfs -mkdir -p /user/$USER/input
```

Upload the input file:

```bash
hdfs dfs -put input.txt /user/$USER/input
```

Verify:

```bash
hdfs dfs -ls /user/$USER/input
```

---

## 🔹 Submit WordCount Job to YARN

Run the MapReduce job using HDFS paths:

```bash
hadoop jar wordcount.jar WordCount \
/user/$USER/input \
/user/$USER/output
```

The job is submitted to the YARN ResourceManager and executed as a YARN application.

---

## 🔹 View HDFS Output

```bash
hdfs dfs -cat /user/$USER/output/part-r-00000
```

The output contains the word counts generated by the MapReduce job.

# 🔄 Local Mode vs Pseudo-Distributed Mode

| Feature         | Local Mode               | Pseudo-Distributed Mode            |
| --------------- | ------------------------ | ---------------------------------- |
| Execution       | Single JVM               | Hadoop cluster services            |
| Storage         | Linux filesystem         | HDFS                               |
| Scheduling      | None                     | YARN                               |
| NameNode        | Not required             | Required                           |
| DataNode        | Not required             | Required                           |
| ResourceManager | Not required             | Required                           |
| Best suited for | Fast development/testing | Demonstrating cluster architecture |
